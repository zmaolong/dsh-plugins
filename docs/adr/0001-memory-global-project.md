# 0001 记忆采用全局 + 项目双作用域，数据放在用户目录

- 状态：已采纳
- 日期：2026-11-09
- 背景：`dsh-agent-extension` 增加「记忆」能力，需要回答三个问题：记忆要不要分全局与项目、数据存在哪、项目如何识别。

## 决策

1. **双作用域**：`global` 记忆属于用户、跨项目可见；`project` 记忆属于一个项目。检索时合并，冲突不自动覆盖，保留多条并标注来源，由用户或模型判断。
2. **用户目录 vault**：记忆内容只写插件 home（默认 `~/.dsh/agent-extension/memory/`），项目内只写一个身份文件 `.dsh/agent-extension/memory/config.json`，并自动加入 `.git/info/exclude`。项目记忆不写入仓库，导出通过下载 Markdown 完成。
3. **项目身份优先取 git `origin` 远程 URL**（规范化、去凭证、去 `.git`），因此 worktree 与独立克隆共享同一份项目记忆；无 origin 时退回首字母排序的第一个远程；无远程退回 git common dir；无 git 退回工作目录路径。身份解析后钉入 `config.json`，用户手改即覆盖，插件不再重写。
4. **一个事实一个 Markdown 文件 + 每作用域一个 `MEMORY.md` 索引**，索引由插件重写，JSON 只存设置、统计与项目登记。

## 理由

参考实现里 claude-mem 与 ZCode 只做项目级、Codex 只做用户级全局，没有任何一家覆盖「全局偏好 + 项目事实」双层；而用户场景（跨项目的工具约定与单仓库的坑）同时需要两者。把长期记忆放用户目录，既避免自动写入污染仓库，也让索引缓存可随时重建；项目内保留最小身份文件，解决了「同一个仓库被克隆到多个目录、或在多个 worktree 中打开时记忆地址错乱」的问题。

## 放弃的方案

- **项目记忆写仓库 `.dsh/memory/`**：会污染工作区、可能泄露会话内容，且需要双向同步规则；团队共享需求交给 `AGENTS.md` 与仓库文档。
- **按目录路径哈希做项目身份**：多 worktree/克隆各自孤立，正是要避免的错乱。
- **SQLite/向量库**：宿主没有 embedding 接口，插件要求零运行时依赖；关键词检索 + 模型精排已够用。
- **外部常驻 worker 进程**：DSH 插件应在进程内完成捕获与召回，外部进程带来安装与端口治理成本。

## 后果

- UI 需要项目选择器与「项目已用目录」信息；身份解析失败时项目作用域会给出明确提示。
- 记忆内容不随仓库迁移；需要交接时用导出功能。
- 身份文件被本地 exclude，`git status` 保持干净；用户若想提交该文件，需自行移除 exclude 行。
