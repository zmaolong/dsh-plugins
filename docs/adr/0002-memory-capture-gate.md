# 0002 自动捕获用「便宜闸门 + 轮末提炼」，记忆过时用两票制

- 状态：已采纳
- 日期：2026-11-09
- 背景：自动记忆的核心风险是 token 成本与漏记、以及记忆过时后不再可信。需要在「每轮都调模型」与「只靠手动写入」之间取平衡。

## 决策

1. **轮末异步提炼，不阻塞对话**：`agent/turn-stopping` 只做闸门与入队；提炼在后台任务中执行，同一会话单运行 + 单排队（新的排队覆盖旧的），失败静默重试一次，`agent/disposed` 时补一次全量补漏（可关）。
2. **闸门不调模型**：子代理会话、空轮、用户输入过短且无工具活动 → 跳过；用户显式请求（「记住/以后都/别用/never」等）→ 跳过闸门直接提炼。本轮已捕获过则跳过。
3. **提炼输入只取本轮增量**：人类消息 + 助手结论 + 工具名/改动路径 + 既有记忆索引；输出 0–3 条结构化 JSON，`maxTokens=1000`、低温度；模型路由取当前会话最近一次请求头，可后续配置低成本模型。
4. **写入即去重**：内容指纹相同则只强化原条目（提升强化计数与时间），不新增；提炼结果携带 `supersedes` 时旧条目标记 `stale`。
5. **过时两票制**：`memory_forget`（模型工具）、`/forget`（用户命令）、`supersedes`（新事实取代旧事实）各计一票；第一票 `stale`（不注入、仍可检索），第二票 `archived`（默认不可见）。管理界面可手动恢复或彻底删除。
6. **模型也可主动维护**：`memory_save` / `memory_forget` 工具与 `/remember` 命令共用同一存储与去重逻辑；删除只走界面或 `/forget`，避免模型误删。

## 理由

参考实现里 ZCode 每轮末用受限子代理提取、Codex 启动时批量总结旧会话、claude-mem 用 hook 逐工具观察——后两者成本或延迟更高。DSH 已有 `session/event` 与 `agent/turn-stopping`，可以在轮末拿到本轮增量并异步提炼；闸门与强制信号保证「贵的地方少调用、用户明确要求的一定落到」。两票制让模型与用户都能纠正过时记忆，同时保留一次审计窗口，避免一次误判直接丢失内容。

## 放弃的方案

- **每轮无条件提炼**：成本与延迟不可控，且多数轮次没有可长期复用的事实。
- **只在会话结束提炼**：记忆滞后，长会话中后段无法用上刚形成的经验。
- **靠模型每轮自行判断是否记忆**：占用 attention 且不稳定，无人兜底。
- **一次标记即硬删除**：误判不可恢复；改为先 `stale`、再 `archived`，并保留手动删除。

## 后果

- 设置页暴露自动捕获开关、会话结束补漏开关、提炼模型配置点与命中率统计；用户可据此调低开销。
- 捕获质量取决于提炼提示词与本轮增量；`memory_save` 的存在保证关键事实还有显式通道。
- `stats.json` 会保留最近 100 个会话的注入/命中计数，用于调整注入条数。
