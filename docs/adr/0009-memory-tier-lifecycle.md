# 0009 记忆保留分层：短期/长期生命周期与注入收紧

- 状态：已采纳
- 日期：2026-11-11
- 背景：记忆子系统 v2（[ADR-0005](0005-memory-recall-v2.md)、[ADR-0006](0006-memory-capture-and-maintenance.md)、[ADR-0007](0007-memory-schema-v2.md)）交付后真实使用一天的实测数据（详见 [`packages/dsh-agent-extension/docs/memory-write-quality.md`](../packages/dsh-agent-extension/docs/memory-write-quality.md)）显示写入/消费严重失衡：捕获一天写入 82 条，但 usage 派生记录里仅 9 条被用过 1–2 次；维护 Run 的规则预筛对新鲜库筛出 0 个候选。用户确认本轮以「避免无效记忆写入」为目标，并定调生命周期分层：默认写入短期记忆，一段时间没用落到待停用直至删除，有使用即升级为长期。

## 决策

1. **schema v3**：记忆条目新增 `tier: short | long` 字段。`MEMORY_SCHEMA = 3`；自动迁移把存量条目（v1/v2）一律补为 `long`，迁移备份目录按来源版本命名（`.backup-v<from>-<timestamp>`）。
2. **写入定级**：`memory_save` 工具与会话末提炼（`source: tool/capture`，未来含 `import`）进入 `short`；用户显式途径（面板新建/编辑保存、`/remember` 命令，即 `source: user`）直接 `long`。`store.save` 缺省按 `source` 推断，显式传 `tier` 优先；`pinned: true` 视为长驻意图（更新时置 `long`）。
3. **升级依据是使用事实证明**，只有两个触发点：
   - `memory_get` 正文读取命中（`store.promoteRead`，由工具执行层挂钩）；
   - 指纹强化（同一事实被再次写入确认）。
   `memory_search` 命中只刷新派生 usage，不触发升级——摘要行被返回不等于内容被消费。
4. **注入收紧**：会话首步索引快照只注入 `long` 条目（`recall.ts` 层过滤）；`short` 条目仍可被 `memory_search` 检索到，检索命中后再 `memory_get` 即升级，形成「被用到才算数」的闭环。注入预算（每层 20 条 / 3,000 字符）不变。
5. **升级写回真源**：tier 是生命周期属性而非使用计数，变更写回 Markdown frontmatter（区别于 `usedCount/lastUsedAt` 只进可重建的 usage.json）；升级是单次元数据变更，不刷新 `updatedAt`。
6. **面板**：列表卡片对 active 且 short 的条目显示「短期」徽章（长期不显示以降噪）；详情弹窗显示层级徽章并提供手动升降级（`POST /memory/tier`，与 `/memory/status` 对称的最小动作语义）。

## 理由

- 无效记忆的最大成本不在存储，而在它后续占用的每一次注入、检索与维护预算；分层把「值不值得长期保留」从写入时的预测改为写入后的事实证明（参考 codex 的 usage 淘汰与 agentcairn 的「是否蒸馏」二值判决，见参考项目调查记录）。
- 用户显式写入（面板、命令）代表人的直接判断，不应被观察期拦截；模型自动捕获才是低质写入的主要来源，先进短期观察。
- 存量条目全部升为 `long`：一次性把 82 条在用记忆降回短期会让它们批量进入停用轨道，过于激进；分层只约束新写入，存量按既有维护流程处理。
- `memory_search` 不触发升级：若摘要命中即升级，agent 一次宽泛检索就能把大量短期条目洗白成长期，观察期形同虚设。

## 放弃的方案

- **全量注入 + 事后维护清理**（v2 现状）：维护预筛对新鲜库失明已被实测证伪，且无效条目在被清理前已消耗多轮注入预算。
- **给写入加 LLM 打分门槛**：agentcairn 的实践表明浮点分数噪声大（0.3–0.5 聚集），「是否愿意蒸馏/是否被使用」的二值信号更可靠；且零运行时依赖约束下没有小模型通道做前置分诊。
- **观察期内阻止检索**：短期条目完全不可见会造成「明明记得写过却查不到」的体验倒退；检索可见、命中升级是更平滑的过渡。

## 后果

- schema v3 迁移随插件加载自动执行（先备份再写回）；旧版插件读 v3 文件会把 `tier` 视为未知字段透传，行为等同 v2。
- 注入索引的候选池变小：新写入的短期条目在升级前不出现在首步快照中，依赖检索的场景需要模型主动 `memory_search`（工具描述已说明该机制）。
- 维护 Run 的预筛规则尚未感知 `tier`（延迟评审进 B7 批次），本批短期条目的闲置淘汰暂不生效。
- 面板保存的 `source` 从 `capture` 修正为 `user`（`/memory/save` 路由），既有行为缺陷顺带修复。
